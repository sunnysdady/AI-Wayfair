# 数据上传 → 自动分析：架构与后端路线

## 现在（方案 1，已上线）：浏览器端跑真 Python

上传中心「0. 上传并当场重算分析」：用户选月度 YB 工具表 xlsx →
浏览器用 **Pyodide（WebAssembly）跑和本地完全相同的 Python 脚本** →
当场预览新任务清单、下载重算后的 CSV。

```
数据上传中心页面
  └─ reports/assets/analysis-engine.js   ← 唯一的"接缝"
       WFAnalysis.run(ybFile) ──→ _runPyodide()
          1. 加载 Pyodide + pandas + openpyxl
          2. fetch /scripts/*.py            （单一来源，不复制）
          3. fetch /assets/baseline/*.csv.txt（基准输入，build_all 自动刷新）
          4. 写入上传的 xlsx
          5. runpy 跑 build_product_pricing_health.py → build_ops_workbench.py
          6. 读回产物 CSV，返回统一结构
```

关键：**分析逻辑零改写、零分叉**——浏览器跑的就是 `scripts/` 里那两个脚本。

边界：方案 1 只"算给你看 / 下载"，**不改动线上网站**。要让线上正式版更新，
仍需维护者把 CSV 落库后跑 `build_all.sh` 部署——或上后端（方案 2）。

## 将来（方案 2）：后端自动分析

目标：上传后服务器直接跑分析并回写线上，全自动。
**接缝已经留好**——只需两步，上传中心页面无需任何改动：

1. 在 `analysis-engine.js` 把 `WFAnalysis.backend` 改成 `"api"`。
   `_runApi()` 已写好：POST 文件到 `/api/analyze`，期望返回与 `_runPyodide`
   **完全相同的结构** `{ pricingCsv, tasksCsv, profilesCsv, taskRows, taskCount }`。

2. 实现 `/api/analyze`（Vercel Python Serverless Function，跑同一份脚本）：

```python
# api/analyze.py（草图）

import json, tempfile, pathlib, runpy

        # 3. runpy 跑 build_product_pricing_health.py → build_ops_workbench.py
        # 4. 读回产物 CSV，按统一结构返回 JSON
        ...
```

进一步（真正"回写线上"）：后端跑完把产物 commit 到仓库或写入
对象存储 + 触发 Vercel 重新部署。这一步涉及凭证与部署权限，属于不可逆/影响外部，
落地前需确认。

## 为什么这样设计

- **单一事实来源**：浏览器和后端跑同一份 `scripts/*.py`，不会出现"两份实现漂移"。
- **基准不过期**：`build_all.sh` 里的 `refresh_browser_baselines.py` 每次重建自动把
  `data/` 基准镜像到 `reports/assets/baseline/`。
- **可逆**：方案 1 纯前端、无后端、文件不出本机；方案 2 是加法，不推翻方案 1。

## 已知限制（方案 1）

- 首次运行要下 ~8MB Pyodide 运行时（之后浏览器缓存）。
- 当前只支持替换"月度 YB 工具表"这一项输入；catalog / 分级 / 库存映射用随页面
  附带的基准快照。要支持替换更多输入，在 `BASELINES` 增加上传位即可。
- 依赖浏览器能访问 jsdelivr CDN（取 Pyodide）。
