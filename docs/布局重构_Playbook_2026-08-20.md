# Wayfair AI 运营中台：布局重构 Playbook

> 2026-08-20 审计更新：SKU 经营中心的首屏队列已从 4 条示例数据改为 Catalog 只读数据驱动。Product Management 指标仅在已匹配时展示；未匹配或读取失败时明确提示，不再以静态数据代替生产事实。

**目标：** 让运营人员在 10 秒内看清「今天该处理什么、哪个 SKU 有风险、下一步要做什么」，并能在不切换多个页面的情况下完成判断与闭环。

## 1. 本次诊断

### 已确认的事实

- 当前侧栏同时承载一级工作域、页面入口与展开的二级菜单；展开「商品与库存」后，系统入口被挤到首屏外，层级感弱。
- 「商品与库存」的四个子项并列，但分别是数据、库存、流程文档和经营动作，分类维度不一致。
- 现有「SKU 经营」页面的主数据是父 Listing 的运营角色、利润审计和历史 Part 明细，适合审计，不足以支持日常 SKU 经营。
- 现有产品模块已具备库存、商品资料、推新与经营数据基础；本次重构不要求先迁移或重算这些数据。

### 关键结论

把「SKU 经营」放在商品模块的最后一个二级入口，会把最需要持续处理的工作放到最深处。它应升级为 **商品经营的默认工作台**；库存、商品资料和新品则成为围绕 SKU 决策的专业子工作区。

## 2. 新的信息架构

侧栏只放全局工作域，不再展开二级菜单。模块内导航放进内容区顶部的本地导航，避免全局与局部层级混杂。

```text
总览
工作台
  ├─ 今日优先
  ├─ 闭环任务
  └─ 日报
商品经营
  ├─ SKU 经营中心（默认）
  ├─ 商品资料与质量
  ├─ 库存与供给
  └─ 新品孵化
广告增长
  ├─ 广告管理器
  ├─ 商品投放表现
  ├─ 优化工作台
  └─ 优化复盘
计划与复盘
  ├─ 本月经营计划
  ├─ 推广节奏
  ├─ 月度复盘
  └─ 历史档案

侧栏底部工具：数据源与同步状态｜帮助
```

### 命名替换

| 现有名称 | 新名称 | 原因 |
| --- | --- | --- |
| 商品与库存 | 商品经营 | 从资料分类改为运营目标 |
| SKU 经营 | SKU 经营中心 | 明确它是日常决策入口 |
| 商品数据 | 商品资料与质量 | 覆盖资料完整性与 Listing 质量 |
| 库存更新 | 库存与供给 | 覆盖库存状态、补货与异常 |
| 推新 SOP | 新品孵化 | 用业务任务名替代文档名；SOP 作为页面内指导 |
| 日报 | 工作台 / 日报 | 日报是日常动作的一部分，不与经营域并列 |
| 数据源 | 数据源与同步状态 | 明确这是系统工具，而非运营工作域 |

## 3. 页面布局标准

### 全局骨架（桌面端）

```text
┌──────── 216px 全局侧栏 ────────┬──────────────────── 内容区 ────────────────────┐
│ 品牌 / 当前店铺                │ 面包屑 · 页面标题 · 数据更新时间 · 主操作          │
│                                ├─────────────────────────────────────────────────┤
│ 总览                           │ 本地导航 / 日期 / 店铺 / 状态筛选                  │
│ 工作台                         ├─────────────────────────────────────────────────┤
│ 商品经营                       │ 核心指标或异常摘要                                 │
│ 广告增长                       ├─────────────────────────────────────────────────┤
│ 计划与复盘                     │ 列表 / 看板 / 图表                    详情或动作面板 │
│                                │                                                     │
│ 数据源与同步状态               │                                                     │
│ 帮助                           │                                                     │
└────────────────────────────────┴─────────────────────────────────────────────────┘
```

- 全局侧栏固定为 `216px`；一级入口高度 `44px`，不展示常驻子菜单。
- 页面顶部使用单行标题区：标题、数据更新时间、一个主要操作。避免标题、筛选和按钮各占一行。
- 本地导航为内容区的横向 Tabs；在窄屏可横向滚动，不挤压主表格。
- 数据列表与详情分栏只在 `≥1440px` 常驻显示；小于该宽度时，详情改抽屉或全页，主列表保持可读。
- 所有状态均有文字，不只依赖紫色高亮；点击区域最小 `44 × 44px`。

### 页面共同顺序

1. **判断层**：页面标题、数据更新时间、关键筛选、主操作。
2. **异常层**：本页 3–5 个最需关注的指标或异常，而非堆满所有指标。
3. **处理层**：可排序的列表、看板或任务队列。
4. **证据层**：任务记录、数据来源、操作结果与更新时间；默认折叠，按需展开。

## 4. SKU 经营中心：必须补齐的工作闭环

### 页面定位

SKU 经营中心不是报表页，而是「分层 → 判断 → 分派动作 → 留存证据」的工作台。父 Listing、子 SKU/Part 之间必须能切换，且在同一个实体上下文中查看。

### 首屏结构

1. **标题与全局筛选**：店铺、日期范围、经营阶段、负责人、异常等级。
2. **经营雷达**：在售 SKU、P0/P1 风险、低库存、待处理任务、目标达成率。
3. **经营分层**：全部 / 增长 / 维稳 / 修复 / 清货 / 新品。每类显示数量与最紧急异常。
4. **SKU 队列**：默认按风险和到期动作排序，不按静态名称排序。
5. **SKU 360 详情**：右侧抽屉或详情页，承接判断与行动。

### SKU 队列的最低字段

| 字段 | 回答的问题 |
| --- | --- |
| SKU / Listing 与层级 | 现在看的是父体、子体还是 Part？ |
| 经营分层与健康状态 | 它要增长、维稳、修复还是退出？ |
| 销售与趋势 | 近周期表现是在改善还是恶化？ |
| 库存可售天数 | 是否会断货或积压？ |
| 投放 / 利润信号 | 广告和已知费用后的贡献是否异常？ |
| 下一步动作 | 谁在何时处理什么？ |
| 数据新鲜度 | 此判断所依据的数据是否过期？ |

### SKU 360 详情页签

- **概览**：经营阶段、核心判断、最新异常、下一步动作。
- **销售与流量**：销量、转化、趋势与异常来源。
- **商品质量**：内容完整性、图片/属性/变体问题与 Listing 状态。
- **库存与供给**：可售、在途、预计断货或积压风险。
- **广告与利润**：投放表现、费用、贡献上限与预算建议。
- **任务与证据**：待办、负责人、截止时间、结果链接、回滚说明。

原有的「运营角色 / 利润审计 / 历史 Part 明细」保留在“广告与利润”及“历史证据”中，不能继续作为 SKU 页面唯一主视图。

## 5. 交互与状态规则

- **全局导航回答“去哪儿”**；本地导航回答“在这里做哪类工作”；页内 Tab 回答“对这个对象看什么”。三层不可混用。
- 任何 SKU 风险至少显示：风险等级、触发原因、数据时间、负责人、建议动作。
- 从库存、广告、商品质量页面点到 SKU 时，必须保留 SKU 上下文，不能回到无筛选的总表。
- “推新 SOP”不再独立占用入口；根据新品阶段，在新品详情中呈现相应 SOP 和检查清单。
- 表格数据默认服务行动：首列固定实体，末列固定“下一步动作”；低频审计字段放入详情，不挤占主视图。

## 6. 实施顺序

### P0：先整理壳与导航（不改数据）

1. 将全局导航收敛为「总览、工作台、商品经营、广告增长、计划与复盘」。
2. 将日报移入工作台；将数据源与帮助移入底部工具区。
3. 移除侧栏展开式子菜单，在各模块内容区新增本地导航和统一标题栏。
4. 完成命名替换，尤其将「SKU 经营」升级为「SKU 经营中心」。

### P1：补齐 SKU 日常经营能力（复用现有数据）

1. 以现有运营审计、商品资料、库存和广告数据组成 SKU 队列。
2. 建立经营分层、风险解释、数据新鲜度和“下一步动作”字段。
3. 将现有只读的父 Listing / 利润审计内容收进 SKU 360 详情。

### P2：实现真正闭环

1. SKU 详情能新建或关联闭环任务，并回写处理状态与结果证据。
2. 任务中心能按 SKU / Listing 聚合，日报与月度复盘能引用同一条经营记录。
3. 所有跨页跳转保留店铺、日期、SKU/Listing 筛选条件。

## 7. 验收标准

- 在 2 次点击内进入任一 SKU 的经营详情。
- 1366px 宽度下，侧栏、工具入口和页面主列表均不被遮挡；导航不出现横向滚动。
- 每条 SKU 队列记录在首屏回答：当前状态、最大风险、下一步动作。
- 库存、广告、商品质量的异常均能跳转到同一 SKU 的详情上下文。
- 任务具备负责人、截止时间、状态与结果证据；没有证据的任务不得显示为“已完成”。

## 8. 本次审计边界

本 Playbook 基于当前界面截图与现有前端信息架构/数据视图进行梳理。未修改生产页面、未改变数据口径，也未替代登录后真实数据的可用性测试；P1 开始前应用一组真实 SKU（增长、缺货、低效投放、新品各至少一条）验收上述闭环。
