## 三条总则（任何回答都先服从）
1. **真实成交优先于广告归因。** Report Center 的 Sales/Orders 是平台真实成交；WSP 的"广告订单/销售额"是 14 天 view-through 归因（偏宽、滞后），不等于真实成交。先看真实成交，广告数据只用来发现浪费和机会。
2. **结构安全 > 流量效率 > 平台利润 > 履约风险。** 中大件不能用"小件爆款思维"，没有结构利润的低价放量越卖越亏。
3. **带数字、零臆造。** 报表里没有的字段，结论标"数据缺失，待补"，不留空、不编。

## 〇、阈值速查卡（最常用，先看这张）

### 利润 / 成本
| 口径 | 安全 | 一般 | 危险 |
|---|---|---|---|
| 订单毛利率 | ≥30%（可考虑加预算） | 20–30%（仅小预算测试） | <20%（不投广告、不进促销） |
| 月复盘毛利闸 | ≥25% 健康 | 15–25% 一般 | <15% 差 |
| 平台空间率（= (Retail Price Net − Total Cost) / Retail Price Net） | ≥16% | — | <16% 偏低 |
| Base Cost / 前台价 | ≤72% | — | >72% 红线（先别提 Base） |

> 平台空间 = `Retail Price Net − Total Cost`；`Total Cost = WholesaleCost + Ship Outbound + Incident/Return + Product Allowance + Other Handling…`。WholesaleCost 能赚 ≠ 平台口径能赚。

| CVR | >2%（弱于类目即承接差） |
| ROAS | 放量要求 ≥4 或自然单强；结合真实利润 |
| 样本量 | 真实成交 ≥3 件才算有效信号，<3 件走"验证" |
| 止损线 | 28 天有花费且真实成交 0 → 止损 |
| AI Bidding 前提 | 近 30 天 ≥20 单；学习期 14 天 |
| WSP 初始 Bid | 建议价 +30%；新品 2–3 倍测试 |
| Keyword Target 预算占比 | ≤30% |
| 广告归因期 | 14 天；每 1–2 周复盘 |

### 承接 / Listing（VFL）
| 维度 | 标准 |
|---|---|
| Recommended Tag Coverage | ≥95% 最优、≥80% 合格 |
| 图片 Browse Hero | ≥1000×1000px |
| Reviews | ≥20 条 |
| 评分 | ≥4.0 星 |

### 库存 / 闭环
- 放量库存闸：可用量 **≥10 且覆盖 ≥2 周销量**；低于先补货，缺货则广告降最低止血。

## 一、系统结构与信息架构

本系统是一个**纯静态 HTML 运营看板门户**（无构建框架，部署在 Vercel），把 Wayfair 店铺运营拆成"门户导航 + 报告页 + 工具页 + 复盘引擎"。

### 1.1 信息架构（五分组）
1. **今日工作**：执行中心（唯一工作入口）。
2. **执行清单**：SKU 任务清单、待办甘特图、WSP 调整清单等。
3. **分析与档案**：店铺诊断、SKU 经营档案、定价体检、复盘报告。
4. **数据与工具**：数据上传中心、每日库存生成、库存映射、周复盘浏览器工具。
5. **规则与背景**：帮助中心、操作护栏、店铺交接、本知识库。

> 执行中心是唯一工作入口；任务执行状态存 localStorage（key：`wf2:<taskId>`），执行中心与任务清单共享，互相同步勾选。

### 1.2 关键文件与脚本
| 路径 | 作用 |
|---|---|

| `reports/*.html` | 报告页，统一壳由脚本生成 |

## 二、复盘方法论 v2（周复盘 + 月复盘）

### 2.1 周 vs 月分工
- **周复盘** = 快速止损 + 小预算验证（盯广告浪费、补救承接、抢量词）。输入：订单数据 + WSP 5 类广告报表。
- **月复盘** = 结构性诊断（账号→类目→SKU→投放，重排预算、SKU 分层）。输入：近 28 天 WSP 5 类 + 当月 Report Center 报告。

### 2.2 输入数据
- **WSP 5 类**：Campaign、Product、Keyword Targeting (Listing)、Keyword Optimization、Search Term Research。
- **Report Center（月）**：Account Overview / Business Performance、Sales Dashboard、Detailed Listing Health、Option Drill Down、Cost Stack、Customer Feedback（有几张用几张）。
- **口径对齐**：广告报表=近 28 天滚动窗口，Report Center=自然月，两窗不重合。**结构判断（真实成交/毛利/承接）以 Report Center 为准；广告效率用 28 天广告报表。**
- **数据有效性闸**：每张报表"有数据行 + 字段完整"才纳入；空表 / To-Date 残表 / 字段缺失沿用上一份有效完整月报作基线并标注。

### 2.3 四道闸（每个 SKU 进四象限前逐一过）
1. **真实成交闸** — 用 Report Center 真实订单/件数为主信号。WSP 0 归因但有真实成交 → 不判止损。
2. **利润闸** — 真实订单毛利率 ≥25% 健康 / 15–25% 一般 / <15% 差；平台空间率 ≥16% 安全；Base/前台价 ≤72%。成本未给时"放量"只算候选，标"待毛利确认"。
3. **库存闸** — 可用量 ≥10 且覆盖 ≥2 周才允许放量；低于先补货；缺货广告降最低；无数据标"待库存确认"。
4. **闭环闸** — 上期动作"结果"先回填，验证成功才推广、失败才止损。

### 2.4 SKU 四象限
| 象限 | 判定 | 动作 | 可否推广 |
|---|---|---|---|
| **放量** | 真实≥3、毛利≥25%、库存健康、CVR 不弱、广告可解释(ROAS≥4 或自然单强) | 加预算/促销，7 天复查 | 提炼打法复制到同系列 |
| **修复** | 有流量或历史订单，但 TAG/图片/评分/CVR/配送任一短板明显 | 先修承接，再开广告 | 修复后连续两周达标再推广 |
| **验证** | 样本<3 件但信号好，或自然单强广告弱 | 小预算小范围短周期测试 | 成功两轮才进放量池 |
| **止损** | 28 天有花费且真实成交 0，或毛利/库存/客诉/评价严重拖累 | 暂停广告/促销或下架候选 | 不推广，除非修复证据明确 |

### 2.5 诊断框架（逐层）
| 层级 | 核心问题 | 输出 |
|---|---|---|
| 账号 | 销售额变化来自流量、转化还是客单价？(业绩=流量×转化×客单价) | 本月主矛盾 + ≤3 个经营动作 |
| 类目 | 类目涨跌是否跑赢大盘？谁拖累？ | 类目机会/止损/修复优先级 |
| SKU | 放量、修承接、验证还是退出？ | SKU 四象限动作清单（每条带该 SKU 数字） |
| 投放 | 广告在放大好 SKU 还是给坏承接输血？ | 预算重排/抢量词/无效组合止损 |

### 2.6 五项交付物 + 动作账本字段
交付物：① 全盘结论（最大问题+最大机会）② SKU 矩阵 ③ 方法库（赢家打法+可复制条件）④ 动作账本 ⑤ 下月目标（Revenue/CVR/AOV/ROAS 各一量化目标）。
动作账本每条填满：**对象 / 级别(P0·P1·P2) / 类型(放量·修复·验证·止损·进攻·别误杀) / 决策(带数字) / 原因(真实数据) / 负责人 / 截止日 / 复盘指标(现值→目标) / 下次复查日 / 状态 / 结果(复查回填) / 推广规则 / 止损规则。**

### 2.7 HTML 报告输出规范
诊断完成生成**单文件 `.html`**：所有 CSS 内联、无外部字体/CDN/图片（断网/邮件/打印可用）；必含 7 区块（报告头+口径声明 / KPI 概览 / 全盘结论 / 账号·类目诊断 / SKU 四象限 / 投放动作 / 动作账本+下月目标），**禁止空区块**，缺数据写"待补+原因"；优先级与象限用色块标签（止损红/修复琥珀/验证蓝/放量绿）、数字等宽右对齐；主动作 ≤3。详见 `.claude/skills/wayfair-monthly-review/SKILL.md`。

## 三、供应商履约绩效卡（Supplier Scorecard）解读

绩效卡 ≠ 销售/广告复盘，它衡量**履约稳定性**，直接喂 Wayfair 配送承诺；持续红灯会拉长时效徽章、压低转化，严重时触发账号绩效警告——**优先级高于一切广告优化**。

### 3.1 指标分组与读法
- **时效组**：DS–SP–OTS（小件 ≤1.4 天）、DS–LP–OTS（大件 ≤2.7 天）= 下单到发货工作日数。
- **交运组**：Induction Fill Rate（≥93%）= 发货后承运商首次揽收扫描占比；低 → 货"确认发货"但没真正交到承运商（备货慢/揽收排期长/面单或尺寸被拒）。
- **质量组**：GIE as % of WSCNR = 事故/货损支出占比（偏高 = 大件破损/退货成本失控）；Inventory Inaccuracy（<0.51%）。
- **纪律组**：Single/Multiple Order Delay、Supplier Driven Cancellation、RP Performance（Pass）——这些绿了说明接单纪律好。
- **数据不足**：Return Rate 等用滞后口径（如本月用两月前），数据不足不判定，下期补。

### 3.2 诊断逻辑
1. 先看红灯，**红灯优先于一切**。
2. **找同源根因**：大件 OTS 高 + 首扫率低 高度同源（都指向"货没及时交到承运商")，应合并成一条"大件交运提速"动作，而非两条。
3. 时效/首扫红灯 → 给订单打时间戳（下单→打单→备货完成→揽收→首扫），定位最长那段；导出无首扫订单逐单查因。
4. GIE 高 → 按"破损/缺件/错发/退货"拆因，大件优先升级外箱+护角+栈板。
5. **缩写口径不确定就标注**，让用户向 RM（asiasupplierservicedesk@wayfair.com）要指标定义表再精修动作。

### 3.3 输出
一张红黄绿分级的"绩效卡解读+行动卡"：总览(几红几黄几绿) → 逐项(值/目标/超标程度) → 根因 → P0 派工(对象+负责人+截止) → 下月目标(现值→目标)。可渲染成 PNG 直接发运营（脚本：`scripts/make_scorecard_card.py`）。

## 1. Wayfair 运营总认知

Wayfair 不应按普通爆款平台理解，尤其是中大件产品。核心不是单纯低价、广告或冲销量，而是：

`结构安全 + 流量效率 + 平台利润 + 履约风险可控`

### 1.1 平台本质

- Wayfair 更接近供应商主导供给、平台控制前台价格与流量分配的交易平台。
- 卖家承担产品供给、库存管理、履约结构、包装和售后风险。
- 平台关注终端消费者体验、履约稳定、退货/破损风险和平台自身利润。
- 平台前台售价由 Wayfair 动态定价，供应商不能完全控制。
- 卖家主要能控制：Base Cost/供货价、包装结构、物流方式、库存、广告、促销、Listing 内容和售后风险。

### 1.2 中大件产品特殊性

中大件产品的主要风险：

- 运费高。
- 破损率高。
- 退货成本高。
- 单 SKU 风险大。
- 包装尺寸、重量、包裹数量会直接影响成本、流量和平台判断。

因此，中大件不能用“小件爆款思维”做。低价放量如果没有结构利润，可能越卖越亏。

### 1.3 常见误区

| 误区 | 正确认知 |
|---|---|
| 销量低就是运营没做好 | 也可能是供货价、履约成本、售后风险、Listing 承接或平台利润问题 |
| 降价一定带来销量 | 降价可能压缩利润，若 CVR 不提升就是无效降价 |
| 多仓一定有优势 | 多仓扩大覆盖，但增加库存和资金占用，新品需谨慎 |
| 广告能解决一切 | 广告只能放大已有结构，不能修复亏损 SKU |
| 亏损是阶段性投入 | 中大件亏损放量会放大售后、退货和尾程成本 |

## 2. 店铺经营公式与指标体系

### 2.1 店铺复盘主公式

`GMV = 流量 × CVR × AOV`

其中：

- 流量：Sessions、Impressions、Clicks。
- CVR：转化率，反映流量承接能力。
- AOV：客单价，反映产品结构和关联销售能力。

### 2.2 广告和促销判断公式

`单访客价值 = CVR × 单品净收益`

广告成立条件：

`单访客价值 > CPC`

促销成立条件：

- 折扣后单品净收益仍为正。
- 促销后的 CVR 提升足以弥补折扣损失。
- 广告和促销叠加后仍不触及亏损线。

### 2.3 订单毛利口径

YB 工具表 `订单处理` 中的订单毛利公式：

`毛利润 = (回款价 × 94% - 采购成本) × 数量`

该口径说明：

- 已经扣了 6% 费用。
- 未扣广告支出。
- 未扣客诉、退货、扣款。
- 未扣仓储、人工、固定开支和汇损。

### 2.4 大促利润口径

YB 工具表 `产品上架` 中的大促利润逻辑：

`大促利润 = 折后 Base Cost × 80% - 拿货成本`

该口径预留约 20% 平台/损耗/费用安全垫，但真实经营仍需结合广告、客诉、Cost Stack、退货和仓储判断。

### 2.5 Cost Stack 口径

`Total Cost = WholesaleCost + Ship Outbound + Incident/Return + Product Allowance + Other Handling 等`

结论：

- `WholesaleCost` 不是总成本。
- WholesaleCost 看起来能赚钱，不代表平台口径能赚钱。
- 若平台空间 `Retail Price Net - Total Cost` 偏低，或物流/退货/补贴成本异常，不能直接投广告或进促销放量。

## 3. 广告投放知识库

### 3.1 广告产品矩阵

| 产品 | 作用 | 备注 |
|---|---|---|
| WSP | 搜索页排名 / 搜索引流 | 基础投放工具 |
| WSD | 展示广告 | 最低预算约 `$1,000/月`，仅限 WFUS B2C |
| WSD New SKU | 新品展示资源包 | 最低预算约 `$750/月` |
| WSS | 品类页面顶端曝光 | 初始最低预算约 `$500/月`，按月度 ROAS 结算 |
| Google PLA | 站外 Google 流量 | Wayfair 团队运营，按 CPC 付费 |
| MWSP | 官方代投 | 适合缺人力、广告新手、扩展阶段 |
| AI Bidding Target ROAS | 自动出价 | 过去 30 天累计 `≥20单` 后再用 |

### 3.2 WSP 快速启动

路径：

`Partner Home → Products → Advertising → Wallet`

启动规则：

- 首次充值建议不低于 `¥1,600`。
- 必须开启 Automatic Payments。
- 初始 Bid：建议价 `+30%`。
- 新品 Bid：建议价 `2-3倍` 做测试。
- 优先 Product Target。
- Keyword Target 预算占比 `≤30%`。
- 广告归因期：`14天`。
- 每 `1-2周` 下载报告复盘。

### 3.3 广告漏斗阈值

| 指标 | 参考值 |
|---|---|
| Impression | `>1000` 后再判断趋势 |
| CTR | `0.7%-1%` |
| CVR | `>2%` |
| ROAS | 结合品类和真实利润判断 |
| AI Bidding 前提 | `≥20单/30天` |
| AI Bidding 学习期 | `14天` |

### 3.4 广告诊断四步

1. Impression 是否 `>1000`？
   - 不足：加关键词、提高出价、扩大流量。
2. CTR 是否达到 `0.7%-1%`？
   - 不足：查主图、标题、价格、评价、竞争力。
3. CVR 是否 `>2%`？
   - 不足：查库存、PDP、Listing、促销、配送承诺。
4. ROAS 是否达到真实利润要求？
   - 不足：降 CPC、降预算、暂停，或先修 Listing / 成本结构。

### 3.5 三种广告情形

| 情形 | 特征 | 动作 |
|---|---|---|
| ROAS 高、花费低 | 有利润但量小 | 出价调到建议价 `130%-150%`，新品可试 `1.5-2倍` |
| CTR 低、CVR 高 | 转化好但点击少 | 优化主图标题，适当调出价/预算，拓展展示 |
| CTR 高、CVR 低 | 点击多但不买 | 不加预算，先查价格、Listing、评价、库存、促销 |

### 3.6 广告准入规则

订单毛利率 `<20%`：

- 不投广告。
- 不进促销。
- 先复核采购成本、Base Cost、包装物流、客诉/退货原因。

订单毛利率 `20%-30%`：

- 只做小预算测试。
- ROAS 和真实利润都过线才保留。
- 不做大促放量。

订单毛利率 `>30%`：

- 仍需检查 Cost Stack、TAG、CVR、库存和客诉。
- 全部通过后才考虑加预算。

平台空间偏低或成本异常：

- 不进大促。
- 广告低效的先暂停或降到最低预算。
- 先查 Ship Outbound、Incident/Return、Product Allowance、Other Handling。
- 再决定是否调 Base Cost、优化包装履约、退出促销或清退 SKU。

## 5. SKU 分层、去留与止损

SKU 去留必须靠数据，不靠感觉。判断维度：

- 真实盈利。
- Cost Stack。
- CVR。
- CTR。
- Impression。
- 库存。
- 客诉/退货。
- Listing 健康度。
- Review 数量和星级。
- 是否有未来 60-90 天修复机会。

### 5.1 S 级：核心优质 SKU

目标：

- 持续放量。
- 保持健康利润。

动作：

- 优先保证库存。
- 不轻易降价。
- 广告预算在 ROI 合格后可增加。
- 按季节节奏做广告和促销。

前提：

- 真实利润为正。
- Cost Stack 健康。
- CVR 合格。
- 库存不断货。
- 客诉风险可控。

### 5.2 A 级：潜力 SKU

目标：

- 验证潜力。
- 避免库存断档。

动作：

- 小预算测试。
- 轻量促销。
- 修 Listing。
- 观察 ROI 和 CVR。

### 5.3 B 级：滞销或低效 SKU

目标：

- 降低库存占用。
- 减少资源浪费。

动作：

- 查 Listing。
- 查价格。
- 查 Cost Stack。
- 查库存和履约问题。
- 能修则小范围测试，不能修则清库存。

### 5.4 C 级：边缘 SKU

目标：

- 轻量管理或止损。

动作：

- 不加广告。
- 不进大促。
- 只保留必要库存动作。
- 若 60-90 天无改善机会且无法形成正向现金流，建议退出。

### 5.5 SKU 健康颜色

| 颜色 | 含义 | 行动 |
|---|---|---|
| Red | 必填 TAG 未完整 | 立即补全必填 TAG |
| Yellow | 必填 100%，推荐内容 `<80%` | 补充推荐内容 |
| Green | 必填 100% + 推荐 `≥80%` | 维持并优化 |
| Blank | 缺少必填信息 | 重新填写必填项 |

## 6. 定价、DPA、LDP 与放量逻辑

### 6.1 定价核心原则

- 定价不是单纯成本加成。
- 价格失去竞争力，CVR 会明显下滑。
- 定价必须结合市场同类产品价格、产品差异化、履约成本、平台利润和卖家真实利润。

### 6.2 价格上限与下限

价格上限：

- 不是理论最高价。
- 是销量效率开始明显下降的价格点。
- 可通过 CVR 曲线、竞品、类目参考和利润效率判断。

价格下限：

- 是参与竞争的生存线。
- 低于该线即使有销量，也可能没有经营意义。
- 需计算结构成本、市场价格带、流量效率和真实利润。

### 6.3 有同款与无同款放量

有全网同款：

- 市场价决定价格锚点。
- Wayfair 结合全网同款和自身 Cost Stack 决定前台售价。
- 结构优于市场平均水平，平台更可能给流量。

无全网同款：

- 平台会给试探性价格和测试流量。
- 关键看 CTR、CVR 和单访客价值。
- 测试期表现差，会快速失去流量。

### 6.4 DPA 和 LDP

DPA：

- Wayfair 系统根据市场竞争动态调价。
- 供应商无法完全控制最终展示价。
- 供应商要确保 DPA 后仍有合理利润。

LDP：

- Partner Home 2.0 可通过 Content Management Table 查看 LDP Margin。
- 可比对竞争对手定价。
- 可参考 Merchandising Team 定价建议。

### 6.5 三大可控成本

| 成本 | 优化方向 |
|---|---|
| 包装成本 | 减少体积，降低材料成本 |
| 物流时效 | CastleGate 可提升排名，减少广告成本 |
| 退货率 | 降至 `≤4.3%`，减少逆向物流损耗 |

### 6.6 主力价格区间参考

| 品类 | 价格区间 |
|---|---|
| 书桌 | `$100-$375` |
| 办公椅 | `$49-$176` |
| 床 | `$45-$104` |
| 猫爬架 | `$50-$200` |
| 书柜 | `$45-$375` |

## 7. 物流、CastleGate、MSBD 与库存

### 7.1 MSBD

MSBD = Must Ship By Date，必须发货截止日期。

关键参数：

- 截单时间：下午 `5:00 PM`。
- Base Lead Time：`2小时`，工作日计算。
- 承运商取货日：周一 / 周三 / 周五。
- Induction Fill Rate = 在 MSBD 前完成首次承运商扫描的订单比率。
- Induction Fill Rate 会影响 Scorecard 中 Incident Rate。

### 7.2 CastleGate vs Dropship

| 维度 | CastleGate | Dropship |
|---|---|---|
| 发货方 | Wayfair 仓库 | 供应商仓库 |
| 配送速度 | 更快，如 2 日达 | 依赖供应商 |
| 备货提前量 | 通常 4-6 周 | 实时同步 |
| 适用 | 稳定 SKU、可预测需求 | 测试 SKU、灵活履约 |

### 7.3 备货节奏

| 场景 | 提前量 |
|---|---|
| CastleGate 头程 | `4-6周` |
| Way Day | `8-12周` |
| 黑五 | `9-10周` |
| 常规旺季 | `6-12周` |

### 7.4 库存与资金

首次备货：

`首次备货 = 日均预测销量 × (测试周期 + 二次补货周期)`

安全库存：

- 结合月销量、补货周期、在途周期、季节性波动计算。
- S/A 级 SKU 优先保障。
- B/C 级 SKU 不应因沉没成本继续压资金。

### 7.5 履约结构优化

重点：

- 包裹数量。
- 尺寸。
- 体积。
- 重量。
- 包装抗摔。
- 尾程成本。
- 退货和破损率。

原则：

- 包裹不是越少越好，也不是越多越好。
- 要在快递尺寸/重量限制、破损率、客户安装体验之间平衡。
- 包装优化要做跌落测试。

### 7.6 扣款争议

路径：

`Partner Home → Finance → Accounts Receivable → Deductions`

处理：

- Accept。
- Contest / Dispute。

有效期：

- 争议有效期 `14天`。
- 超时自动接受。

### 7.7 Scorecard 指标

| 指标 | 上限 | 影响 |
|---|---|---|
| Cancellation Rate | `≤1%` | 不达标可能无法参加促销 |
| Return Rate | `≤4.3%` | 影响账号健康 |
| Incident Rate | `≤2.5%` | 影响评分和平台信任 |

## 9. 账号业绩诊断 SOP

### 9.1 月度复盘 5 步

1. 销售额与流量趋势是否合理正增。
2. 做 MoM 和 YoY 同期对比。
3. 定位 Recipes 异常，是广告投放还是其他来源。
4. 分析优质产品 SKU / Priority Set。
5. 聚焦不超过 3 个重点，落实成实际动作。

培训课照片补充口径：

- 主公式固定为 `业绩 = 流量 × 转化 × 客单价`。
- 账号层先判断销售额和流量涨跌是否成正比，转化率是否大幅下降。
- 类目层看 Sales Dashboard 的 Revenue、Units Sold、产品数、YoY Trend，判断是否与类目大盘一致。
- SKU / Parts 层用 Option Drill Down 和 Detailed Listing Health 查 Total Revenue、MoM、YoY、Sessions、CVR、TAG、图片、价格、配送、评价。
- 经营能力层拆到健康库存、促销活动、广告引流、准时可靠配送、文案图片、客户评价和无损交付。
- 每次复盘不超过 3 个重点，必须落到负责人、截止时间和复盘指标。
- 周复盘的数据输入固定为订单数据 + WSP 五类广告报表：Campaign Report、Product Report、Keyword Targeting Report (Listing)、Keyword Optimization Report、Search Term Research Report。
- Campaign / Product 用于判断停、降、保留、加预算；Keyword Optimization / Keyword Targeting / Search Term Research 用于判断停词、降 bid、扩词和搜索词机会。
- Report Center 月报不阻塞周复盘；只在有效导出后进入月度结构诊断。

| Partner Home → Reports & Business | 各项指标趋势 | 重点关注 YoY |

### 9.3 诊断 / 放量准入

| 对象 | 通过条件 | 拦截条件 | 动作 |
|---|---|---|---|
| 放量 SKU | 有订单、正毛利、库存健康、CVR 不弱于类目、广告 ROAS 可解释 | 库存不足、评分低、客诉未闭环、广告 0 单高消耗 | 小预算测试，7 天复盘订单、ROAS、库存消耗 |

## 11. 合规与报告

### 11.1 合规判断

合规不是所有报告都必须做，而是要按品类、国家、后台提示和销售区域判断。

重点问题：

- 产品是否接触儿童。
- 是否涉及化学材料。
- 是否涉及防火、电器、燃气。
- 是否进入加拿大等有额外报告要求的市场。
- 后台是否提示缺报告。

### 11.2 常见报告

- 儿童类产品：CPC、ASTM F963、CPSC 等。
- 加拿大站：可能受 SOR/2016 系列等报告影响。
- 家居类：防火、化学、电器、燃气等按品类稽查。
- 非强制报告：如环保、绿标等，需评估成本收益，不一定都值得做。

### 11.3 合规 SOP

1. 判断品类和销售区域。
2. 查看后台提示。
3. 检查是否接触儿童、化学材料、电器燃气等风险。
4. 联系第三方检测或服务商确认报告清单。
5. 优先补齐会影响链接销售或国家站点销售的强制报告。
